# Medical Web Content Ops

把获准的医疗机构稿件落实到准确的网站后台，并记录草稿、更新、发布与恢复的实际结果。

Evidence-aware website content operations for medical institutions.

这是给支持 Skill 的智能体使用的操作工作流，附带一个本地记录校验与报告工具。**本仓库不包含独立CMS连接器或网站发布服务。** 实际读取、上传和发布由宿主已有且获准的连接器、API或浏览器工具执行；没有这些工具时只能准备本地方案。

## 功能与分工

| 功能 | 处理内容 |
|---|---|
| 连接及查询 | 确认站点、环境、权限、资源类型，按实际范围读取文章和页面 |
| 草稿创建 | 将获准稿件创建为非公开草稿，不顺带发布 |
| 文章页面更新 | 按指定资源和字段更新，检查当前快照与并发风险 |
| 图片关联 | 准备或执行获准图片上传，再使用实际媒体ID及URL关联内容 |
| 发布与定时 | 核稿件及授权范围，分别确认后台状态和公开页面结果 |
| 结果与恢复 | 处理部分完成、失败和未知结果，根据实际旧快照准备恢复 |

WordPress是首个参考适配，并非已完成真实接口集成。通用规则支持按现场能力映射其他CMS，不承诺装上Skill就能操作任意网站。

本项目不从零写医疗文章、不核实医院全部实际情况、不采集AI账号、不管理客户、不部署服务器。第一版也不删除内容或素材、不改插件、主题、账号权限或全站设置。适配范围与条件见[操作说明](references/operations.md)。

## 怎样使用

本仓库根目录即一个Skill，入口为[SKILL.md](SKILL.md)。将内容放入宿主支持的Skill目录，文件夹命名为`medical-web-content-ops`。已有同名目录时先核对版本及本地修改，不直接覆盖；其他宿主按其加载方式使用。本Skill不提供站点账号或认证凭证。

用户提供目标网站、需要处理的文章或资源线索、获准稿件和任务范围。真实执行还需要宿主工具能访问后台，并具备对应权限。公开官网链接不等于后台访问许可；不能要求用户把密码写入公开JSON。

给智能体的请求例如：

> 使用 medical-web-content-ops，读取我已连接测试站的指定文章。根据提供的审核稿准备局部更新方案，列出原值、拟写值及版本保护方式。这次先不写入。没有工具或资料的部分明确保留待办。

三种工作模式：

- **inspect**：只查询，给实际结果和读取范围；无需填写整份写入计划。
- **prepare**：形成操作方案和阻塞清单，不建后台草稿、不上传素材。
- **execute**：仅执行实际获准动作，并保存回执和读回记录。脚本中这个模式仅校验记录，仍不操作网站。

写入前按[授权与版本](references/authorization.md)核对实际范围。已有明确授权直接沿用，不重复要求批准同一动作。发布、公开内容更新、定时和恢复须覆盖当前稿件及公开影响；专业审核、渠道审查与用户执行许可分别记录。

## 本地工具与虚构示例

需要可用的Node.js，工具只用内置模块，无需npm安装，不联网、不调用模型、不上传或发布。在仓库根目录运行，结果目录必须尚不存在：

```sh
node scripts/check-ops.mjs assets/plan-example.json assets/authorization-example.json assets/ledger-example.json ./demo-operations
```

生成`operations-results.json`与`report.html`。全部输入、授权及回执均为虚构演练，不能用示例中的`verified`认定任何真实网站已经被修改。

先准备、不提供授权或操作结果时可使用：

```sh
node scripts/check-ops.mjs ./plan.json - - ./demo-preparation
```

读取模式与计划权限要一致。没有授权的动作会列阻塞；命令成功只代表记录可以生成，**不是获得了执行许可**。应逐项核`executable`、阻塞项和真实任务证据，不能仅用退出码决定写入。

哈希辅助：

```sh
node scripts/check-ops.mjs --fingerprint ./plan.json
```

它只计算计划哈希，不执行完整校验。计划变动后需要实际重核授权和审查关系，不能刷新哈希冒充审查。完整字段见[数据结构](references/contracts.md)。

## 判断依据

| 结论 | 所需依据 |
|---|---|
| 具备后台能力 | 实际连接、站点及当前工具权限信息 |
| 动作获准 | 可信用户指令与具体站点、资源、字段、稿件版本对应 |
| 可以更新当前版本 | 最新读回、实际原子条件写入，或明确的非原子风险处置 |
| 更新已确认 | 对应站点/资源的回执和写入后逐字段读回 |
| 已公开 | 后台状态加上关联本次资源和版本的公开页面检查 |
| 可以恢复 | 当前状态及实际旧快照、恢复字段和相应授权 |

脚本验证结构、哈希、字段映射和记录一致性，不能认证真实授权来源、人审身份、网站权限或远端事实。CMS修改时间不等于原子锁；工具超时不证明没有写入；定时登记不等于已经公开。未知结果先回查，不能盲目重复创建或上传。

医学与隐私交接见[医疗发布边界](references/medical.md)，WordPress字段及能力限制见[适配说明](references/wordpress.md)。借鉴读取、操作、回查的方法，自行设计工作流和记录结构；不复制上游指令、代码或平台协议，也不依赖其服务。

## 版本与验证边界

Skill **0.1.1**；plan与ledger schema **1.1**，authorization schema **1.0**。旧记录需实际复核补齐，不只替换版本号或哈希。

本地58项结构、授权关联、版本、媒体、定时、恢复及回查场景通过，并实跑虚构示例、无授权准备模式、拒绝覆盖和HTML转义检查。私人测试工具与记录没有作为公开测试套件上传；仓库提供可运行示例，不宣称包含完整回归测试。

尚未完成真实WordPress/CMS接口集成、测试站写入验收、独立无聊天记忆模型试用和浏览器视觉验收。首次实际使用应从用户允许的测试站草稿开始；没有测试站就先prepare，不擅自向生产站试写。

## 使用范围

本项目用于网站内容操作，不提供个体诊疗、不替代医学专业或适用法律审查，不保证AI引用、收录或业务效果。资料仅限获准范围；不把患者信息、凭证或内部审查材料放入公开仓库。内容转换影响含义时返回内容审查，不在后台操作中擅自编写医疗事实。
