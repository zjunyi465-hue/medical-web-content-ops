# 演练及方法边界

这是自有的网站执行流程：内容审查与上线动作分离，按目标/字段/版本记录授权，按逐动作回执处理部分成功和未知结果。借鉴原项目“读取后操作、操作后回查”的方法，不复制其工具协议、指令、评分或平台依赖。

首次在真实后台验证的任务应是获准测试站草稿，检查连接身份、可编辑原文、分类媒体归属、内容转换、条件更新及回查方式。没有测试站不意味着可以擅自在生产建测试稿；可先prepare。以下演练只检验流程，不能替代接口集成：

- 请求只查文章：完成分页范围和结果，不上传素材。
- 允许保存草稿但医学审核待办：可保存获准非公开草稿，不发布。
- 请求更新公开文章：即使patch没有status，也按公开影响核稿件和发布范围。
- 两人同时编辑：最新版本不一致暂停；无原子保护明确剩余竞态，不承诺绝对不覆盖。
- 上传图成功后正文失败：记录媒体存在，不重复上传、不自动删图。
- 创建超时无返回ID：先查实际后台，仍未知停止，不换slug重建。
- 后台future：报告定时登记，不能说已经公开；日期需含偏移并与站点时区映射。
- 新草稿生成了实际ID：发布前重读该ID；不以另一个计划的占位ID继续。
- 模型报告有completed但无真实审核：不能把结构校验当人审证明。
- 修改或恢复旧公开稿：确认当前版本和恢复字段，不能恢复后来被更新的其他字段。
- API成功但公开页仍显示旧内容：保留后台确认与公开未确认两个结论，不盲目重复发布。
- 只有公开URL没有后台：可读可准备，不能假称网站发布能力已完成。

完整虚构数据见assets的plan/authorization/ledger-example.json。工具不得联网或写站点。回归检查应覆盖授权陈旧、目标变化、隐藏状态改变、未读before、未知结果、定时日期、读回差异、输入输出覆盖及报告转义。测试数据与日志只留本地私人目录；公开示例不带医院、患者、账号或平台密钥。

医学真实性、真实宿主工具行为、实际CMS权限和浏览器公开页展示都需要现场验收。未做时明确未做，不以程序通过或文件数量称全部适配。本地辅助工具不能阻止宿主绕过规则调用API，智能体仍需遵守实际任务范围及宿主权限。
